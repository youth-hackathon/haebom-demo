# haebom-demo

해봄 체험 환경입니다. 브라우저에서 Android 폰 4대 가운데 하나를 골라 직접 써 봅니다. 폰 화면을 누르는 것은 보는 사람이고, 해봄은 다음에 누를 곳만 짚습니다.

전체가 Docker 안에서 돕니다. 내 컴퓨터에서나 서버(VM)에서나 같은 명령으로 띄우고 같은 주소 모양으로 엽니다.

```bash
cp .env.example .env            # 비밀번호와 여는 범위를 적습니다
mkdir -p secrets                # 모델 키, 음성 키를 넣습니다 (아래 "키" 참고)
docker compose up -d --build
```

- 체험 페이지: <http://127.0.0.1:6080/haebom/> (https는 `https://127.0.0.1:6443/haebom/`)
- 처음 켤 때는 Android 이미지(약 2GB)를 받고 폰 4대를 만들어서 15~20분 걸립니다. 그동안 페이지에는 폰이 "켜지는 중"으로 나옵니다. 두 번째부터는 2~3분입니다.

## 폰을 고르고, 쓰고, 돌려주기

폰은 잠금입니다. 한 사람이 고르면 그 사람이 놓을 때까지 다른 누구도 그 폰을 고르지 못하고, 그 폰의 화면 주소에도 닿지 못합니다.

| 순서 | 페이지 | 서버가 하는 일 |
|---|---|---|
| 들어오면 | 폰 4대가 "비어 있어요 / ○분째 사용 중 / 켜지는 중"으로 나옵니다. 누가 폰을 고르거나 반납하면 새로 고침 없이 바로 바뀝니다 | 폰 목록을 바뀔 때마다 밀어 줍니다(server-sent events) |
| 폰을 고르면 | 그 폰을 쓰는 화면으로 넘어갑니다. 쓰는 중인 폰은 눌리지 않습니다 | 그 폰을 이 브라우저의 것으로 적고(쿠키), 폰을 처음 상태로 돌립니다: 안내 멈춤, 쓰던 앱 끄기, 글자 크기 1.0, 알람 지우기, 해봄 앱의 "이어서 하기" 기록 지우기. 그런 다음 해봄 앱을 띄워 둡니다 |
| 쓰는 동안 | 왼쪽에 폰 화면, 오른쪽에 할 일 고르기와 안내 진행 | 다른 브라우저가 이 폰을 고르면 409, 이 폰의 화면 주소(`/devices/<폰>/…`)를 열면 403 |
| 사용 끝내기 | 첫 화면으로 돌아갑니다 | 안내를 멈추고 홈 화면으로 돌린 뒤 잠금을 풉니다 |
| 페이지를 닫으면 | | 30초 뒤에 잠금을 풉니다 |
| 그냥 두면 | 1분 전부터 화면 아래에 "○초 뒤에 폰을 반납해요, 계속 쓰기"가 뜹니다 | 10분 동안 조작이 없으면 잠금을 풉니다 |

잠금이 풀리는 때는 위의 셋뿐입니다.

- **페이지가 열려 있는지**는 페이지가 열어 두는 연결(`/haebom/api/hold`)이 살아 있는지로 압니다. 페이지의 타이머에 기대지 않으므로, 브라우저 창이 가려지거나 최소화되어 타이머가 느려져도 잠금이 풀리지 않습니다.
- **조작**은 세 군데서 봅니다: 페이지가 알려 주는 누름과 키(폰 화면 안을 누른 것 포함), 폰이 스스로 적는 마지막 입력 시각, 앱이 남기는 안내 진행. 폰을 만지고 있는 사람에게서 폰을 가져가지 않으려는 것입니다.
- 누가 어느 폰을 쓰는지는 파일(`api-data` 볼륨)에 적어 둡니다. 시연 API를 다시 띄워도 잠금이 남습니다.

한 브라우저가 한 번에 한 대를 씁니다. 새로 고침을 하거나 같은 브라우저에서 다시 열면 쓰던 폰으로 돌아갑니다. 시간은 `.env`의 `LEASE_IDLE_S`로 바꿉니다.

호스트의 adb(`127.0.0.1:6520`~)는 이 잠금을 거치지 않습니다. 폰에 입력을 보내는 도구는 먼저 페이지나 `POST /haebom/api/claim`으로 그 폰을 잡고 씁니다.

폰을 쓰는 화면의 구성입니다.

| 자리 | 내용 |
|---|---|
| 왼쪽 | 실제 Android 폰 화면. 마우스로 누르고 끌 수 있고, 키보드 입력도 들어갑니다. 아래에 소리 켜기, 마이크 켜기, 처음 상태로 버튼이 있습니다 |
| 오른쪽 위 | 할 일 고르기. 검증된 매뉴얼이 있는 일은 카드로 나오고, 그 밖의 일은 직접 적습니다 |
| 오른쪽 가운데 | 안내 진행. 단계마다 무엇을 안내했는지, 누가 답했는지(매뉴얼 / 폰 설정값 / AI / 기다림), 답하는 데 걸린 시간 |
| 오른쪽 아래 | 지금 폰의 실제 값(글자 크기, 켜진 알람). 안내가 "다 했어요"라고 말하는 근거입니다 |

폰 화면, 터치, 키보드, 소리, 마이크는 모두 WebRTC로 오갑니다. 소리와 마이크는 브라우저 정책 때문에 버튼을 한 번 눌러야 켜집니다. 마이크는 https 주소나 `localhost`·`127.0.0.1`로 열었을 때만 켤 수 있습니다(브라우저의 제한).

## 구성

```
브라우저 ──http(s)──▶ web ──▶ device   폰 화면(Cuttlefish 웹 클라이언트), WebRTC 신호. 그 폰을 쓰는 브라우저만
   │                   └────▶ api      폰 목록, 폰 고르기와 반납, 안내 시작, 진행 기록
   └──WebRTC(15550-15599)──▶ device    영상, 소리, 마이크, 터치

api ──adb──▶ device                    앱 설치, 접근성 서비스 켜기, 요청 보내기, 로그 읽기, 처음 상태로 돌리기
폰 안의 해봄 앱 ──▶ api ──▶ front ──▶ artemis ──▶ 모델
                      └──▶ tts ──▶ Gemini (음성, 받아 적기)
```

| 서비스 | 하는 일 | 어디서 오는가 |
|---|---|---|
| `kvm-modules` | 호스트 커널에 KVM·vhost 모듈을 올리고 끝납니다 | 이 저장소 |
| `device` | Android 가상 기기 4대(Cuttlefish, 540×1200, 30Hz, 한 대에 CPU 8개와 메모리 4GB). 켤 때마다 한국어·한국 시간·버튼 세 개짜리 바·한글 키보드로 맞춥니다 | Google의 cuttlefish-orchestration 이미지 + `device/entrypoint.sh` |
| `artemis` | 화면을 보고 다음 동작 하나를 고르는 서버. jev 방식으로 답합니다: 누를 곳은 Jev가 고르고, 글자 입력처럼 Jev가 못 하는 단계만 LLM이 답합니다 | [haebom-artemis](https://github.com/youth-hackathon/haebom-artemis) |
| `tts` | 안내 문장을 소리로 바꾸고 말소리를 받아 적는 서버 | [haebom-tts](https://github.com/youth-hackathon/haebom-tts) |
| `front` | 검증된 매뉴얼로 먼저 답하고, 없으면 artemis로 넘기는 서버 | [haebom-manual](https://github.com/youth-hackathon/haebom-manual) |
| `api` | 시연 API. 폰을 한 대씩 내주고 회수하고, 폰을 준비하고, 페이지의 버튼을 폰의 명령으로 바꾸고, 앱의 로그를 진행 기록으로 바꿉니다 | `api/` |
| `web` | 체험 페이지와 프록시(nginx). 비밀번호, https, 폰 화면에 닿아도 되는지 확인 | `web/` |

폰에 설치되는 앱은 `app/haebom-debug.apk`입니다([haebom-app](https://github.com/youth-hackathon/haebom-app) `783b024`을 빌드한 것이고, 서버 주소는 넣지 않고 빌드했습니다). `api`가 폰에 앱이 없거나 다른 빌드면 설치하고, 폰이 다시 켜져도 접근성 서비스와 서버 주소를 다시 맞춥니다.

폰 안의 앱은 `127.0.0.1:8770`(안내)과 `127.0.0.1:8766`(음성)을 봅니다. 이 주소는 `adb reverse`로 `api` 컨테이너에 닿고, `api`가 `front`와 `tts` 컨테이너로 이어 줍니다. 그래서 앱 설정이 어디서나 같습니다.

폰 대수는 `.env`의 `CF_DEVICES`로 바꿉니다. 대수를 바꿔 다시 띄우면 폰을 지우고 새로 만듭니다.

## 키

키는 저장소에 넣지 않습니다. 띄우는 곳마다 `secrets/` 폴더에 넣습니다(`.gitignore`에 들어 있습니다).

| 파일 | 내용 | 없으면 |
|---|---|---|
| `secrets/artemis.env` | haebom-artemis의 `relay/.env.example`과 같은 형식. jev 방식은 `OPENROUTER_API_KEY`(Jev)와 `LETSUR_API_KEY`(LLM)를 씁니다 | 매뉴얼에 있는 일만 안내됩니다. 그 밖의 일은 AI가 답하지 못합니다 |
| `secrets/tts.env` | `TTS_ENGINE=gemini`와 `GEMINI_API_KEY=...` | 안내 소리가 나지 않습니다. 앱은 언제나 Gemini 음성을 청하고, 가상 기기에는 대신 읽을 폰 음성이 없습니다 |

다른 자리에 있는 파일을 쓰려면 `.env`의 `ARTEMIS_ENV`, `TTS_ENV`에 경로를 적습니다. 따로 띄워 둔 음성 서버를 쓰려면 `.env`의 `APP_TTS_BASE`에 그 주소를 적습니다(주소가 로그나 페이지로 나가지 않습니다).

## 서버(VM)에 띄우기

호스트에 KVM이 있어야 합니다. 폰의 속도는 CPU가 정합니다(화면을 GPU 없이 CPU로 그립니다). 클라우드 VM이면 중첩 가상화를 켠 리눅스 VM(폰 4대에 CPU 16개, 메모리 32GB 이상. 예: GCP `n2-standard-16`, `--enable-nested-virtualization`), 내 컴퓨터면 Docker Desktop(WSL2)이나 리눅스의 Docker입니다.

```bash
git clone https://github.com/youth-hackathon/haebom-demo.git && cd haebom-demo
cp .env.example .env
# .env 에서:  DEMO_PASSWORD=<비밀번호>   WEB_BIND=0.0.0.0   WEBRTC_BIND=0.0.0.0
mkdir -p secrets && nano secrets/artemis.env && nano secrets/tts.env
docker compose up -d --build
```

방화벽에서 열 포트는 `6080`(http), `6443`(https), `15550-15599`(tcp와 udp, WebRTC)입니다. 마이크까지 쓰려면 `https://<서버 주소>:6443/haebom/`으로 엽니다. 인증서는 자체 서명이라 브라우저가 경고를 한 번 보여 줍니다. 제대로 된 인증서가 있으면 `web` 서비스의 `/etc/nginx/tls`에 `cert.pem`, `key.pem`을 마운트합니다.

폰이 알려 주는 WebRTC 주소는 컨테이너 안의 주소라서, 페이지가 "이 페이지를 연 주소의 같은 포트"를 연결 후보로 하나 더 넣습니다(`web/www/tune.js`). 그래서 서버의 공인 주소를 따로 설정하지 않습니다.

## 자주 쓰는 명령

```bash
docker compose ps                       # device 가 healthy 면 폰이 다 켜진 것입니다
docker compose logs -f device           # 폰이 켜지는 과정
docker compose logs -f api              # 시연 API
docker compose build --no-cache front   # 매뉴얼을 새로 받아 다시 만들기 (haebom-manual 의 main)
docker compose down                     # 내리기. 폰 상태(볼륨)는 남습니다
docker compose down -v                  # 폰까지 지우기. 다음에 Android 이미지를 다시 받습니다
adb connect 127.0.0.1:6520              # 호스트에서 폰 1에 직접 붙기 (폰 2는 6521, ...)
```

`device/entrypoint.sh`는 컨테이너가 도는 동안 고치지 않습니다. 컨테이너 안에서 실행 중인 그 파일이라, 고치면 실행이 중간에 끊깁니다. 고친 뒤에는 `docker compose restart device`로 다시 켭니다.

## 시연 API

`web`의 `/haebom/api/` 아래에 있습니다. 누가 어느 폰을 쓰는지는 쿠키(`haebom_lease`)로 가립니다. 밖에서 보낸 글자가 폰의 셸에 닿는 곳은 `start`의 `task` 하나이고, 길이를 제한하고 따옴표로 감싸 한 인자로만 넘깁니다. `reset`은 정해진 명령만 실행합니다.

| 요청 | 하는 일 |
|---|---|
| `GET devices` | 폰 목록과 상태(`idle`, `busy`, `offline`), 내가 쓰는 폰(`mine`) |
| `GET devices/stream` | 같은 목록을 바뀔 때마다 밀어 줍니다 |
| `GET hold` | 폰을 쓰는 페이지가 열어 두는 연결. 살아 있는 동안 그 폰은 잠겨 있습니다 |
| `POST claim` `{"device": "cvd_1-1-1"}` | 그 폰을 잠급니다. 남이 쓰는 중이면 409, 켜지는 중이면 503 |
| `POST release` | 잠금을 풉니다 |
| `GET state` | 내 폰의 준비 상태, 이 폰에서 쓸 수 있는 매뉴얼, 폰의 실제 값, 무조작 회수까지 남은 시간. 폰이 없으면 410과 까닭 |
| `GET events?after=<번호>&run=<번호>` | 안내 진행 기록. `after` 뒤에 바뀐 것만 |
| `POST start` `{"task": "글자 크기 키우기"}` | 안내 시작 |
| `POST stop` | 안내 멈춤 |
| `POST reset` | 내 폰을 처음 상태로 |

## 확인한 것

Windows의 Docker Desktop(WSL2, CPU 16개, 메모리 32GB)에서 띄우고, 헤드리스 Chrome으로 페이지를 열어 확인했습니다(2026-11-21). 값은 페이지의 DOM, WebRTC 통계, 시연 API의 답, 폰에 adb로 물은 값입니다.

**잠금**

| 항목 | 확인한 방법 | 결과 |
|---|---|---|
| 첫 화면이 바로 바뀌는지 | 한 방문자가 첫 화면을 보는 동안 다른 방문자가 폰을 고름 | 0.03초 뒤 "사용 중"으로 바뀜(새로 고침 없음) |
| 잠긴 폰 | 다른 방문자가 그 폰을 고르고, 그 폰의 화면 주소를 엶 | 고르기 409, 화면 주소 403 |
| 페이지의 타이머가 멈춰도 | 쓰는 사람의 페이지를 75초 동안 얼림 | 15번 읽어 15번 모두 "사용 중". 얼림을 푼 뒤 그대로 쓰는 화면 |
| 사용 끝내기 | 누른 뒤 첫 화면 | 바로 "비어 있어요". 예전 폰의 화면 주소는 403 |
| 페이지를 닫으면 | 닫은 뒤 폰이 비는 때 | 36초 |
| 고를 때 처음 상태로 | 글자 크기를 1.3으로 바꿔 둔 폰을 고름 | 들어가 보니 1.0 |
| 폰 화면을 누르는 것이 조작으로 세어지는지 | 12초 둔 뒤와, 폰 화면을 누른 뒤의 남은 시간 | 158초 → 178초(그때 한도 180초) |

**화면, 소리, 안내**

| 항목 | 확인한 방법 | 결과 |
|---|---|---|
| 폰 화면 | 페이지 안 영상의 크기 | 폰 1, 폰 2 모두 영상이 옴 |
| 마이크 | 마이크 켜기를 누른 뒤 브라우저가 폰으로 보낸 소리 패킷(가짜 마이크 장치) | 2초에 100개씩 늘어남 (폰 1대일 때 확인) |
| 안내 한 번 전체 | 폰을 고르고 "글자 크기 키우기"를 누름. 대역 사용자가 안내를 따라감 | 해봄 앱에서 시작해 끝까지 감. 매뉴얼 6번, AI 1번, 폰의 `font_scale` 1.0 → 1.15 |
| 음성 | 그 안내에서 앱이 읽은 문장과 브라우저가 받은 소리 | 일곱 문장 모두 Gemini(첫 소리까지 0.6~1.7초), 소리 패킷 2305개 |
| https 포트, 비밀번호 | `https://127.0.0.1:6443`, `DEMO_PASSWORD` | 폰 1대일 때 확인. 비밀번호 없이는 401 |

확인하지 못한 것입니다.

- 클라우드 VM에서는 띄워 보지 않았습니다. 다른 컴퓨터의 브라우저에서 WebRTC가 붙는지는 VM에서 봐야 합니다.
- 시연 API를 다시 띄운 뒤에도 잠금이 남는지는 돌려 보지 않았습니다(그때 다른 사람이 폰을 쓰고 있었습니다).
- 10분 무조작 회수와 1분 전 알림은 한도가 3분이던 때에 확인한 것입니다(132초에 알림, 174초에 회수). 한도를 바꾼 뒤에는 다시 돌리지 않았습니다.
- 말소리가 폰에서 글로 받아 적히는 것(마이크 → 앱의 "말로 하기")은 확인하지 못했습니다.
- 위의 값은 폰이 720×1600·CPU 4개이고 artemis가 baseline 방식이던 때의 것입니다. 폰 사양을 CPU 8개·540×1200·30Hz로, artemis를 jev 방식으로 바꾼 뒤에는 아직 다시 확인하지 않았습니다.

## 이전 방식

`deploy/gcp/`에는 Docker 없이 GCP VM에 Cuttlefish를 직접 설치해 여러 대를 띄우던 스크립트가 남아 있습니다. 그때의 기록과 측정값이 거기 있습니다.
